# WhalePhone Agent

机主正常用手机的同时,agent 在**同一台设备**上把任务办完,全程不碰他的屏幕、焦点、
键盘和剪贴板。配置一次之后不需要电脑,agent 自己在手机上跑。

**思路:给 agent 单独造一块屏。** Android 的输入、焦点、输入法每一层都假设「一人一屏」。
与其在这些全局单例上排队,不如让两边看不见彼此 —— 用 shell 身份造一块**受信虚拟显示器**,
agent 的一切都发生在那上面;用无障碍服务跨屏读写,它是唯一带显示器维度的通道。

## 架构

```
┌──────────────── 手机(自足运行,不需要电脑)────────────────┐
│  Display 0 机主在用  ◄─ 从不触碰 ─  Display N agent 副屏     │
│        ▲                                ▲  flags 0x5e08     │
│        │ 只读:机主在用什么 / 键盘弹着没  │ 读 + 写           │
│  ┌─────┴────────────────────────────────┴──────────────┐    │
│  │ EyesAndHands(无障碍服务)                             │    │
│  │ getWindowsOnAllDisplays 跨屏读 · performAction 写     │    │
│  └─────┬─────────────────────────────┬──────────────────┘    │
│  ┌─────┴──────────────┐ ┌────────────┴──────────────────┐    │
│  │ AgentService 前台服务│ │ ShellBridge(shell UID)        │    │
│  │ 感知→模型→动作 循环 │ │ 由 Shizuku 拉起                │    │
│  │ 每步写进 AgentBus    │ │ 造受信副屏 / 带屏号的按键与启动 │    │
│  └─────┬──────────────┘ └───────────────────────────────┘    │
│  ┌─────┴──────────────────────────────────────────────────┐  │
│  │ 机主这一侧(全部可关,默认只有通知)                        │  │
│  │ MainActivity 对话流 · 通知 · 悬浮球(可语音) · 副屏取景窗 │  │
│  └────────────────────────────────────────────────────────┘  │
└────────┼──────────────────────────────────────────────────────┘
         └─ HTTPS ─► 任意 OpenAI 兼容的 LLM(默认 DeepSeek)
```

一台手机上的触摸、焦点、输入法、剪贴板、导航键**全机只有一份**,所以这道题的实质是
资源隔离,不是自动化。一共量到十类冲突,处理掉八类,音频和悬浮窗可见性两类如实留着。
最难的是焦点:副屏上出现可获焦窗口时,主屏会丢掉自己的焦点窗口,机主的键盘被收起、
他的 App 报「应用未响应」—— 这是同一件事的两个后果。造屏时的 `OWN_FOCUS` 挡住了大头
(副屏已存在后往上面启 App,实测 12 次键盘零掉落),但挡不住**造副屏那一下**。剩下这
一下靠两条:副屏跨任务复用,把造屏压到一个会话一次;以及**事前避让** —— 机主在打字时
agent 停手,因为事后补救不成立(焦点推得回去,键盘推不回来)。判据是键盘弹着**且**他的
输入框最近真在变;只看键盘的话,他把键盘留在屏上走开时 agent 就永远不干活了。
另有一条硬边界:副屏和主屏共用电源组,主屏息屏副屏跟着灭,agent 的可工作时间
因此等于机主的亮屏时间。

## 部署

手机上完成,不需要电脑:

1. 装 [Shizuku](https://shizuku.rikka.app/),按它的引导用**无线调试**启动(Android 11+)。
   它的服务只能由 shell 或 root 拉起,所以**手机每次重启都要重开一次**;
   电脑在手边也可以 `bash scripts/start-shizuku.sh`
2. 装本项目 APK,打开后点「授权 Shizuku」
3. 右上角齿轮里填模型接口,回到主界面说一句要它做什么(或点麦克风说)

无障碍权限不用手动开:开跑前自己打开、收工后自己关掉 —— 常开的无障碍服务会让微信
收银台拒绝付款。只动自己那一项,机主原有的读屏服务不受影响。

**两个可选悬浮窗**(主界面底部,默认关,要「显示在其他应用上层」权限):「看副屏」把
那块看不见的屏按 5 帧/秒搬到主屏一角,只读、哪里都能拖;「悬浮球」不打开 app 也能下
任务,点一下**就地展开成语音**。两个都带 `FLAG_NOT_FOCUSABLE`,不碰焦点也不碰输入法。

**它怎么跟你打交道**:默认一直记着上一件事(对话落盘,关掉 app、进程被回收都不丢),
点右上角「新任务」才清;做完一件事不马上收摊,五分钟内追加任务是零开销;要花钱、要给
人发消息这类它不自己拍板,会停下来问,你在 app、悬浮球或通知里回一句,它接着做。

从源码构建 `./gradlew assembleDebug`,产物在 `app/build/outputs/apk/debug/`。Windows 上
项目路径含非 ASCII 字符时 AGP 会拒绝构建,用 `mklink /J C:\wp <路径>` 对着联接构建。

## 配置项

手机上没有环境变量,等价物是 app 内的配置项(存 SharedPreferences,也可用 adb 广播灌入)。

| 键 | 说明 | 默认 |
|---|---|---|
| `LLM_BASE_URL` | OpenAI 兼容接口的 base url | `https://api.deepseek.com/v1` |
| `LLM_API_KEY` | 接口密钥 | 无,必填 |
| `LLM_MODEL` | 模型名 | `deepseek-chat` |
| `A11Y_AUTO` | 设为 `0` 则不自动开关无障碍权限,由机主自己管 | 开 |
| `IDLE_KEEP_MS` | 做完一件事之后还醒着多久,`0` 表示做完就收 | `300000` |
| `TYPING_IDLE_MS` | 键盘开着但机主一个键都没按过时,多久没动静算他停手 | `10000` |
| `DRAFT_IDLE_MS` | 机主按过键之后,多久没动静算他停手(单列是因为他手里可能攥着一串没上屏的拼音,而「正在组词」从系统外面读不到) | `10000` |
| `OVERLAY_BALL` / `OVERLAY_SCREEN` | 两个悬浮窗上次是开是关,开机后照它恢复 | 关 |
| `DEMO_FEED` | 设为 `1` 把副屏画面写成 PNG,给电脑端 `scripts/vd_view.py` 取景 | 关 |

DeepSeek / Kimi / 智谱 / OpenRouter / 自建 vLLM 是同一套协议,换 base_url 和 model 即可。
